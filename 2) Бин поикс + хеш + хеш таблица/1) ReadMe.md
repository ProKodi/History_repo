



# Бинарный поиск (Binary Search)
Идея:
Работает только на отсортированном массиве. На каждом шаге делит область поиска пополам.

Как работает:
1) Берём середину массива.
2) Сравниваем элемент с искомым:
   1) если равен → нашли
   2) если меньше → ищем в правой половине
   3) если больше → ищем в левой половине
3) Повторяем, пока не найдём или область не станет пустой.

Сложность:
Время: O(log n)
Память: O(1) (если итеративно)

Плюсы: Очень быстрый поиск

Минусы: Требует отсортированных данных


# Хэширование
Преобразуем данные (ключ) в число — хэш с помощью хэш-функции.
Особое  свойство: для одинаковых данных будет одинаковый хеш



# Хэш-таблица (Hash Table)
Структура данных, которая хранит пары:
    ключ → значение

Использует хэш-функцию для быстрого доступа.

Сама таблица представляет из себя массив, где индесы это:
    хеш ключа / количество элементов в массиве


Операции:
* Вставка
* Поиск
* Удаление

Средняя сложность:
O(1)

## Коллизии (важно)
Коллизия — когда два ключа дают один и тот же хэш.

Способы решения:

* Цепочки (chaining) 
  * в одной ячейке список элементов
* Открытая адресация
  * ищем следующую свободную ячейку (линейно, квадратично и т.д.)

Плюсы: Очень быстрый доступ (в среднем O(1))
Минусы:
* Возможны коллизии
* Худший случай: O(n)
* Нужно хорошее хэш-функция
