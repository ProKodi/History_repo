



# Краткий конспект

# Итерационная стратегия разработки ПО

## Основная идея

ПО создаётся не за один проход, а через серию коротких циклов — итераций.

Каждая итерация включает:

1. анализ требований;
2. проектирование;
3. кодирование;
4. тестирование;
5. выпуск рабочей версии.

---

# Ключевые понятия

## Итеративность

Повторение циклов разработки.

## Инкрементность

Постепенное добавление функциональности.

## Эволюционность

Развитие продукта на основе обратной связи.

---

# Отличия от Waterfall

| Waterfall                        | Iterative                            |
| -------------------------------- | ------------------------------------ |
| Все требования фиксируются сразу | Требования уточняются постепенно     |
| Результат только в конце         | Рабочие версии после каждой итерации |
| Изменения дорогие                | Изменения — часть процесса           |
| Низкая вовлечённость заказчика   | Постоянная обратная связь            |

---

# Преимущества итерационного подхода

* раннее обнаружение ошибок;
* снижение рисков;
* быстрый выпуск MVP;
* гибкость;
* постоянная проверка гипотез;
* адаптация под рынок.

# Недостатки

* риск накопления технического долга;
* сложность управления;
* необходимость опытной команды;
* высокая вовлечённость заказчика.

---

# Спиральная модель Боэма

## Основная идея

Разработка идёт по виткам спирали с обязательным анализом рисков.

Каждый виток = отдельная итерация.

---

# 4 квадранта спиральной модели

## 1. Определение целей

* требования;
* ограничения;
* альтернативы;
* критерии успеха.

## 2. Анализ рисков

* поиск угроз;
* прототипирование;
* проверка гипотез.

## 3. Разработка и тестирование

* проектирование;
* кодирование;
* интеграция;
* тестирование.

## 4. Планирование следующего витка

* оценка результатов;
* обратная связь;
* обновление рисков;
* план новой итерации.

---

# Особенности спиральной модели

| Характеристика | Значение                         |
| -------------- | -------------------------------- |
| Основа         | Управление рисками               |
| Инструмент     | Прототипирование                 |
| Подходит       | Для сложных и критических систем |
| Недостаток     | Высокая стоимость и сложность    |

---

# Где применяется

* банковские системы;
* медицинское ПО;
* критически важные системы;
* крупные инновационные проекты.

---

# RAD-модель (Rapid Application Development)

## Основная идея

Быстрая разработка приложений через:

* прототипирование;
* повторное использование компонентов;
* тесное взаимодействие с пользователями.

---

# Особенности RAD

* короткие циклы (60–90 дней);
* JAD-сессии;
* CASE-средства;
* параллельная разработка;
* активное участие заказчика.

---

# Фазы RAD

## 1. Планирование требований

Совместное определение бизнес-задач.

## 2. Пользовательское проектирование

Создание и тестирование прототипов.

## 3. Быстрое конструирование

Разработка с использованием готовых компонентов.

## 4. Внедрение

Установка системы и обучение пользователей.

---

# Преимущества RAD

* высокая скорость;
* быстрый вывод на рынок;
* активная обратная связь;
* хорошее соответствие бизнес-потребностям.

# Недостатки

* нужны сильные специалисты;
* высокая вовлечённость заказчика;
* плохо подходит для сложных критических систем.

---

# Agile

## Что такое Agile

Не методология, а философия гибкой разработки.

Основана на:

* адаптивности;
* взаимодействии;
* постоянной обратной связи.

---

# 4 ценности Agile

1. Люди важнее процессов.
2. Работающий продукт важнее документации.
3. Сотрудничество важнее контракта.
4. Готовность к изменениям важнее плана.

---

# Основные принципы Agile

* ранняя поставка ценности;
* приветствие изменений;
* частые релизы;
* тесная работа бизнеса и разработчиков;
* самоорганизующиеся команды;
* постоянное улучшение процессов.

---

# Scrum

## Что это

Agile-фреймворк с фиксированными спринтами.

---

# Основные роли

* Product Owner;
* Scrum Master;
* Development Team.

---

# Основные артефакты

* Product Backlog;
* Sprint Backlog;
* Increment.

---

# Основные события

* Sprint Planning;
* Daily Scrum;
* Sprint Review;
* Retrospective.

---

# Особенности Scrum

* спринты 2–4 недели;
* фиксированный объём задач;
* регулярные поставки инкрементов.

---

# Kanban

## Основная идея

Управление потоком задач через визуализацию.

---

# Особенности

* Kanban-доска;
* WIP-лимиты;
* непрерывный поток задач;
* отсутствие спринтов.

---

# Подходит для

* поддержки;
* сервисных команд;
* проектов с меняющимися приоритетами.

---

# Extreme Programming (XP)

## Основная идея

Максимальное качество кода и инженерных практик.

---

# Основные практики XP

* парное программирование;
* TDD;
* непрерывная интеграция;
* коллективное владение кодом;
* простая архитектура.

---

# Ценности XP

* коммуникация;
* простота;
* обратная связь;
* смелость;
* уважение.

---

# Сравнение Agile-методологий

| Метод  | Особенность              |
| ------ | ------------------------ |
| Scrum  | Управление через спринты |
| Kanban | Непрерывный поток        |
| XP     | Инженерное качество кода |

---

# Рекомендации по выбору модели

| Ситуация                           | Подход            |
| ---------------------------------- | ----------------- |
| Критически важные системы          | Спиральная модель |
| Быстрая разработка бизнес-систем   | RAD               |
| Неопределённые требования          | Agile             |
| Поддержка и сервис                 | Kanban            |
| Высокие требования к качеству кода | XP                |

---

# Основные выводы

1. Итерационные модели лучше адаптируются к изменениям рынка.
2. Спиральная модель делает акцент на управлении рисками.
3. RAD ориентирован на скорость и прототипирование.
4. Agile — философия гибкой разработки.
5. Scrum, Kanban и XP решают разные задачи внутри Agile-подхода.
