



# Краткий конспект

# Методология разработки ПО

Современная разработка ПО — это инженерный процесс, охватывающий весь жизненный цикл программы:
от идеи → до вывода из эксплуатации.

Основная цель:

* управление сложностью;
* обеспечение качества;
* контроль сроков и ресурсов.

Стандарты:

* ISO/IEC/IEEE 12207;
* инженерные методологии управления ЖЦ ПО.

---

# Основные этапы разработки ПО

## 1. Планирование и предварительный анализ

### Цель

Определить:

* зачем создаётся продукт;
* какие проблемы решает;
* какова его бизнес-ценность.

### Основные задачи

* создание бизнес-кейса;
* формирование команды;
* оценка рисков;
* разработка roadmap;
* подготовка ТЗ.

### Артефакты

* Business Case;
* Project Charter;
* Resource Plan;
* Roadmap.

---

# 2. Анализ и сбор требований

## Основная задача

Формализация требований заказчика.

### Включает

* интервью со стейкхолдерами;
* анализ рынка;
* выбор технологий;
* создание SRS/ТЗ;
* проверку требований:

  * на полноту;
  * непротиворечивость;
  * проверяемость.

### Важность

Ошибки на этом этапе самые дорогие в исправлении.

---

# 3. Проектирование системы

## Цель

Преобразовать требования в архитектуру.

### Включает

* проектирование БД;
* архитектуру системы;
* UI/UX;
* безопасность;
* взаимодействие front-end и back-end;
* масштабируемость.

### Виды проектирования

* высокоуровневое;
* детальное.

---

# 4. Программная реализация (кодирование)

## Основные задачи

* написание кода;
* соблюдение coding standards;
* использование Git;
* Unit Testing.

### Технологии

Java, PHP, C++, Python и др.

---

# 5. Тестирование и интеграция

## Цель

Проверка качества и соответствия требованиям.

### Основные виды

* верификация
  (правильно ли построена система);
* валидация
  (тот ли продукт создан);
* регрессионное тестирование.

---

# 6. Внедрение и эксплуатация

### Включает

* развертывание системы;
* настройку инфраструктуры;
* миграцию данных;
* обучение пользователей.

---

# 7. Сопровождение

## Самый длительный этап

### Основные задачи

* исправление ошибок;
* обновления;
* адаптация к новым условиям;
* перенос на новые платформы;
* техническая поддержка.

---

# Распределение трудозатрат

| Этап                      | Доля ресурсов |
| ------------------------- | ------------- |
| Планирование и требования | 15–20%        |
| Анализ и проектирование   | 15–20%        |
| Кодирование               | 25–30%        |
| Тестирование и интеграция | 15–20%        |
| Внедрение                 | 5–10%         |

---

# Модель жизненного цикла (ЖЦ)

## Определение

Модель ЖЦ — структура процессов разработки, эксплуатации и сопровождения ПО.

### Принципы

* модульность;
* распределение ответственности;
* адаптивность под проект.

---

# Стратегии разработки

| Линейная                 | Итерационная              |
| ------------------------ | ------------------------- |
| Последовательные этапы   | Повторяющиеся циклы       |
| Жёсткий план             | Гибкость                  |
| Изменения нежелательны   | Изменения допустимы       |
| Заказчик участвует редко | Постоянная обратная связь |

---

# Каскадная модель (Waterfall)

## Суть

Этапы идут строго последовательно.

### Этапы

1. Планирование
2. Анализ требований
3. Проектирование
4. Разработка
5. Тестирование
6. Поддержка

---

# Плюсы Waterfall

* предсказуемость;
* понятные сроки;
* строгая документация;
* простое управление.

# Минусы

* негибкость;
* позднее выявление ошибок;
* заказчик видит результат только в конце;
* высокая бюрократия.

---

# Где применяется Waterfall

* государственные проекты;
* оборонная промышленность;
* авиация;
* проекты с фиксированными требованиями.

---

# V-образная модель

## Особенность

Каждому этапу разработки соответствует этап тестирования.

| Разработка  | Тестирование                |
| ----------- | --------------------------- |
| Требования  | Приемочное тестирование     |
| Архитектура | Системное тестирование      |
| Модули      | Интеграционное тестирование |
| Код         | Unit Test                   |

### Преимущество

Раннее планирование тестирования.

### Недостаток

Сохраняется негибкость Waterfall.

---

# Итерационные модели

# Инкрементная модель

## Суть

Продукт создаётся частями (инкрементами).

### Плюсы

* ранний рабочий продукт;
* быстрая обратная связь;
* снижение рисков.

### Минусы

* сложность контроля регресса.

---

# Спиральная модель

## Основа

Управление рисками.

### Каждый виток включает

1. Планирование
2. Анализ рисков
3. Разработку
4. Оценку результата

### Особенности

* подходит для инновационных проектов;
* дорогая;
* требует опытных специалистов.

---

# Сравнение моделей

| Критерий          | Waterfall     | Spiral                  | Agile                     |
| ----------------- | ------------- | ----------------------- | ------------------------- |
| Требования        | фиксированные | частично неопределённые | постоянно меняются        |
| Гибкость          | низкая        | средняя                 | высокая                   |
| Участие заказчика | минимальное   | периодическое           | постоянное                |
| Риски             | высокие       | управляемые             | минимизируются итерациями |

---

# Основные выводы

1. Разработка ПО — полный инженерный процесс, а не только кодирование.
2. Жизненный цикл включает анализ, проектирование, тестирование, внедрение и сопровождение.
3. Линейные модели подходят для стабильных проектов.
4. Итерационные модели лучше адаптируются к изменениям.
5. Выбор модели зависит от:

   * масштаба проекта;
   * рисков;
   * стабильности требований;
   * участия заказчика;
   * критичности системы.
